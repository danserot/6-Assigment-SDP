# Подготовка к защите Assignment 6

Автор: Артем Хлоцев. Проект: Smart Code Inspection and Compliance Engine.

## Объяснение за одну минуту

У меня есть дерево проекта: исходники, тесты, конфигурация, зависимости и вложенные папки.
Я хочу выполнять разные операции над одним деревом, не добавляя методы аудита в каждый файл.
Поэтому данные находятся в `model`, операции в `visitor`, результаты в `report`, вывод в `demo`.
Каждый элемент реализует `accept`, а посетитель содержит пять перегруженных методов `visit`.
Новый TechnicalDebtVisitor добавлен отдельным коммитом без изменения элементов.

## Что открыть в IntelliJ

1. Открыть папку с `pom.xml`, дождаться импорта Maven, выбрать JDK 17 или новее.
2. Показать `ProjectElement`, затем `SourceCodeFile.accept` и `ProjectVisitor`.
3. Показать `RecursiveProjectVisitor.visit(Directory)` — обход выполняется здесь.
4. Запустить `Main`: проблемный проект FAILED, исправленный PASSED.
5. Запустить Maven `clean verify` и показать осмысленные тесты.
6. Показать `git log --reverse --oneline` и отдельный коммит с TechnicalDebtVisitor.

## Double dispatch на примере

Переменная имеет тип `ProjectElement`, но объект — `SourceCodeFile`.
Вызов `element.accept(visitor)` выбирает реализацию `SourceCodeFile.accept`.
Внутри неё `this` имеет статический тип `SourceCodeFile`, поэтому компилятор выбирает
перегрузку `visit(SourceCodeFile)`. Затем JVM вызывает её реализацию у фактического
посетителя, например SecurityAuditVisitor. Выбор зависит от обоих объектов.
Без `accept` одна перегрузка по переменной `ProjectElement` этого не обеспечит.

## Какие числа объяснить

В первом проекте 2 исходника, 1 тестовый файл с 6 тестами, конфигурация и pom.xml.
Итого 5 файлов и 374 строки. Средняя сложность `(12 + 8) / 2 = 10`.
Test/source ratio — число тестовых файлов, делённое на число исходников: `1 / 2 = 0.5`.
Это не покрытие тестами. Complexity и Tests проходят, Security не проходит из-за
трёх CRITICAL-проблем. Compliance отдельно находит 5 нарушений, в том числе отсутствие
тестов у модуля user. Quality PASS сам по себе не означает Compliance PASS.
Во втором проекте убраны опасные флаги, указаны версии, добавлен тест user и снижена сложность.

Флаги и метрики заданы вручную в DemoProjects. Программа анализирует модель,
а не исходный код Java и не настоящую базу уязвимостей.

## Важные детали

- `Directory` хранит неизменяемую копию списка. Null-элементы запрещены.
- `accept` только передаёт себя посетителю; дочерние элементы обходит посетитель.
- Для нового анализа создаются новые посетители: их счётчики накапливают результаты.
- `report()` возвращает снимок; повторный вызов не добавляет нарушений.
- Проверка тестов production-модуля не зависит от порядка файлов в дереве.
- Число методов тестов и число тестовых файлов — разные показатели.
- TechnicalDebtVisitor оценивает условное время, а не измеряет реальную трудоёмкость.
- Visitor удобно расширять операциями. Новые типы элементов требуют пересмотра интерфейса
  и посетителей. Strategy меняет алгоритм одной операции и не решает ту же задачу dispatch.
